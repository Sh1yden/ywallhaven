# 🖼 ywallhaven

🌐 Язык / Language **README**: **Русский** · [English](README.en.md)

![icon](docs/assets/icon.svg)

> **Краткое описание:** 🖼️🔍 Десктопное GUI-приложение для поиска, просмотра и скачивания обоев с [Wallhaven](https://wallhaven.cc/). Построено на асинхронном стеке Python и [Flet](https://flet.dev/) — без браузера и лишнего интерфейса, только нативное окно.

## ❔ Зачем вообще проект?

Личный клиент для Wallhaven: искать, фильтровать и скачивать обои сразу из отдельного приложения, без открытия сайта в браузере.

## 🛠 Техно-стек

- **Язык:** `Python 3.13`
- **GUI-фреймворк:** `Flet`
- **HTTP-клиент:** `httpx` (async)
- **Валидация/конфигурация:** `Pydantic` + `pydantic-settings`
- **Пакетный менеджер:** `uv` (build backend: `hatchling` + `hatch-vcs`)
- **Сборка:** `PyInstaller` (Windows `exe` + Linux AppImage через `appimagetool`)
- **Дополнительно:** `Pillow` (ресайз изображений), `packaging` (semver)
- **Тесты:** `pytest`, `pytest-asyncio`, `pytest-cov`
- **Источник данных:** [Wallhaven API](https://wallhaven.cc/help/api)

## 💜 Руководство пользователя

### 🔽 Установка / Быстрый старт

> [!WARNING]
> Убедительная просьба к обычным пользователям: пожалуйста, **НЕ** качайте `pre-release` — он предназначен для разработчиков и тестеров.
> В нём возможны баги и нерабочие функции. Это **бета/альфа** версии.

#### 🪟 Windows

По плану:

1. Зайдите на страницу релизов: [Releases](https://github.com/Sh1yden/ywallhaven/releases).
2. Скачайте `ywallhaven_portable-vX.Y.Z.zip` (внутри папка `ywallhaven` с обоими `exe`). Хотите пофайлово — берите `ywallhaven.exe` + `ywallhaven-updater.exe` отдельно.
3. По желанию проверьте целостность (сверьте хеш с `SHA256SUMS.txt` из того же релиза):

```shell
certutil -hashfile ywallhaven.exe SHA256
```

4. Распакуйте в любое удобное место и запустите `ywallhaven.exe` 💜.

При первом запуске рядом создаются `config.json` (настройки по умолчанию), `favorites.json` (Избранное и коллекции), папка `logs` (логи) и папка `themes` (свои темы + гайд с примерами внутри). [`config.example.json`](config.example.json) — пояснительная шпаргалка с комментариями; готовый набор значений есть в разделе [«Структура конфига»](#-структура-конфига).

#### 🐧 Linux

1. Зайдите на страницу релизов: [Releases](https://github.com/Sh1yden/ywallhaven/releases).
2. Скачайте `YWallhaven-vX.Y.Z-x86_64.AppImage`.
3. По желанию проверьте целостность: `sha256sum -c SHA256SUMS.txt` (файл из того же релиза).
4. Скиньте AppImage в любое удобное место в домашней директории (не в системные папки).
5. Сделайте файл исполнительным и запустите (или просто запустите через файловый менеджер):

```shell
chmod +x YWallhaven-vX.Y.Z-x86_64.AppImage
./YWallhaven-vX.Y.Z-x86_64.AppImage
```

Если система не запускает AppImage, установите `libfuse2` или запустите `./YWallhaven-vX.Y.Z-x86_64.AppImage --appimage-extract-and-run` — подробнее в [FAQ](#-частые-вопросы).

### 🖱 Повседневное пользование

- **Поиск:** введите запрос слева и настройте фильтры: категории (`General`, `Anime`, `People`), `purity` (`SFW`, `Sketchy`, `NSFW`), сортировку и порядок, минимальное разрешение, соотношение сторон, цвет и диапазон `toplist`. Текст применяется с задержкой 0,5 с или по Enter; фильтры — сразу. По тегу можно искать кликом прямо по тегу под превью, по цвету — кликом по кружку цвета там же: фильтр подставится сам.
- **Превью:** клик по картинке в галерее посередине показывает свойства и теги справа. Двойной клик сразу открывает диалог скачивания.
- **Скачивание:** кнопка `Download` → `Original` или подходящий пресет разрешения → диалог сохранения. Если пресет больше исходника (например, для «книжной» картинки), он не предлагается.
- **Обои в один клик:** кнопка с обоями рядом с `Download` ставит текущий арт фоном рабочего стола. Windows подгоняет изображение под экран; на Linux установка делегируется рабочему окружению или Noctalia. Анимированные изображения не поддерживаются.
- **Фулскрин:** клик по превью → кнопки `←/→` листают, колесо/кнопки `−/+` зумируют (зум едет к курсору), тап по фону при зуме не закрывает окно (защита от мискликов).
- **Настройки:** тема, API-ключ, `MODE`, `LOG_LVL`, `PORT`, флаги проверки обновлений и импорт темы. `MODE`, `LOG_LVL` и `PORT` применяются после перезапуска; тема и API-ключ — сразу.
- **Темы:** Settings → Theme (9 встроенных, включая Kanagawa). Свою тему положите как `themes/my_theme.json` рядом с `config.json` или импортируйте кнопкой `Import` в настройках.
- **Избранное и коллекции:** сердечко на миниатюре добавляет обои в Избранное в один клик, `+` открывает пикер коллекций (коллекции, где обои уже лежат, помечены галочкой). Сердечко в шапке открывает режим коллекций: плитки с обложками, создание, свойства, скачивание целиком (ZIP или папкой) и слайдшоу. В открытой коллекции крестик убирает обои, long-press включает множественный выбор (удалить / скачать / перенести / слайдшоу). Подробнее — в разделе [«Система коллекций»](#-система-коллекций).

### ♻ Автообновление

Приложение проверяет релизы при старте, если включён `CHECK_UPDATES`, и по кнопке `Check for updates` в настройках. Порядок такой:

1. Предложит новую версию в диалоге.
2. Скачает файл релиза с прогресс-баром и сверит SHA-256 с digest из GitHub API, если он опубликован.
3. Windows: покажет штатный UAC-запрос (это нормально — помощник обновляет exe в папке установки) → заменит файл и перезапустит приложение.
4. Отклонили UAC — ничего страшного, останетесь на текущей версии; предложение появится позже.

На Linux всё тихо: помощник вшит в `AppImage`, выполняется та же проверка SHA-256, замена файла и перезапуск без запросов — если файл AppImage доступен для записи. Пре-релизы предлагаются только при включённом `CHECK_PRERELEASES`.

### ❓ Частые вопросы

- **В галерее плашка «Wallhaven is down» + кнопка `Retry`.** Упал сам сайт Wallhaven (бывает), приложение ни при чём — код ошибки прямо на плашке. Жмите `Retry` или подождите: приложение само перепроверяет раз в минуту.
- **Пустая сетка / всё висит при пролистывании.** Скорее всего, троттлинг Wallhaven — вставьте API-ключ (раздел ниже), станет заметно бодрее.
- **Windows ругнулся при запуске (SmartScreen).** На текущих релизах это уже не воспроизводится — проверено. Если предупреждение всё же появится, это всё ещё мы: проверьте хеш по `SHA256SUMS.txt`.
- **Не ищет NSFW/sketchy.** Без ключа сайт их не отдаёт — вставьте API-ключ (раздел ниже), разблокируется сразу без перезапуска.
- **AppImage не запускается.** Установите `libfuse2` или запустите с `--appimage-extract-and-run`.
- **Нашли баг.** Создавайте Issue в репозитории и прикладывайте кусок лога из `logs/` (файлы `YYYY-MM-DD-NN.jsonl`) + версию из настроек — так чинится в разы быстрее 💜.

### 🔑 API-ключ: снимаем ограничения Wallhaven

При слишком быстром пролистывании галереи обоев возможно ограничение со стороны сервиса Wallhaven. Поэтому лучше всего выполнить эти действия:

1. Зайдите на сайт [Wallhaven](https://wallhaven.cc/).
2. Зарегистрируйтесь на сайте.
3. Перейдите в [Account Settings](https://wallhaven.cc/settings/account), пункт `API Key`.
4. Скопируйте `API Key` и вставьте его в приложение: поле API-ключа находится в разделе настроек.
5. Пользуйтесь с более высокими лимитами 💜.

Если вы боитесь за приватность данных, а именно за кражу API-ключа: он хранится локально в `config.json` в открытом виде. Даже если ключ попадёт к кому-то ещё, его можно перегенерировать, пользуясь пунктом 3 инструкции выше.

## 💻 Разделы для разработчиков

### 🧰 Разворачивание проекта

1. Клонируйте репозиторий:

```shell
git clone "https://github.com/Sh1yden/ywallhaven.git"
cd ywallhaven
```

2. Синхронизируйте окружение через `uv`:

```shell
uv sync
```

3. Запустите приложение:

```shell
uv run app/main.py
```

Для тестов см. раздел [«Тесты»](#-тесты).

### 📦 Сборка

Основной путь — CI: пушится тег вида `vX.Y.Z`, GitHub Actions собирает обе платформы и сам публикует релиз:

- джоба `test` (`ubuntu-latest` + `windows-latest`) — общий suite и native-тесты; её падение блокирует сборку и релиз;
- джоба `build` (`windows-latest`) — пара `exe`;
- джоба `build-linux` (`ubuntu-22.04`) — AppImage;
- джоба `release` — публикация ассетов;
- тег `vX.Y.Z` → обычный Release;
- тег `vX.Y.Z-rc1` / `-beta` / `-alpha` → pre-release.

В релиз всегда попадают пять файлов: `ywallhaven.exe` (основное приложение, Windows), `ywallhaven-updater.exe` (помощник автообновления, Windows), `ywallhaven_portable-vX.Y.Z.zip` (папка `ywallhaven` с обоими exe), `YWallhaven-vX.Y.Z-x86_64.AppImage` (основное приложение, Linux) и `SHA256SUMS.txt` (контрольные суммы).

Локальная сборка (PyInstaller не умеет кросс-компиляцию — собирайте на целевой ОС):

```shell
uv run python scripts/build.py --target win    # пара exe в dist/
uv run python scripts/build.py --target linux  # dist/ywallhaven/ + хелпер
```

Скрипт запекает версию в `app/core/_version.py` (+ version-info и `.ico` для Windows) и запускает PyInstaller по спекам. Linux-папка сначала собирается в `dist/ywallhaven/`, затем `scripts/make_appdir.py` готовит `dist/AppDir`, после чего `appimagetool` создаёт AppImage:

```shell
uv run python scripts/make_appdir.py
ARCH=x86_64 APPIMAGE_EXTRACT_AND_RUN=1 ./appimagetool \
  dist/AppDir dist/YWallhaven-vX.Y.Z-x86_64.AppImage
```

### ♻ Система автообновления

Приложение проверяет GitHub Releases при старте и по кнопке «Check for updates» в настройках. Порядок работы:

#### 🪟 Windows

1. Сравнение версий семвером по последнему релизу репозитория.
2. Скачивание `ywallhaven.exe` во временную папку с прогресс-баром.
3. Проверка SHA-256 по digest из GitHub API, если он присутствует.
4. Запуск `ywallhaven-updater.exe` через штатный UAC-запрос (помощник с правами администратора), который дожидается закрытия приложения, заменяет исполняемый файл и перезапускает его.

#### 🐧 Linux

Тот же порядок, но без UAC: хелпер вшит в AppImage, цель замены — сам файл `$APPIMAGE`, после замены выполняется `chmod +x` и рестарт. Нужны права записи на файл AppImage; если их нет, помощник сообщит причину.

#### Config

Поведением управляют поля в `config.json` (стандартные значения — в разделе [«Структура конфига»](#-структура-конфига)):

- `CHECK_UPDATES` — проверять обновления при старте;
- `CHECK_PRERELEASES` — предлагать пре-релизы.

Если приложение запущено из исходников, проверка обновлений работает, но применить обновление нельзя — для этого нужен собранный бинарник.

### 🎨 Система тем

#### Встроенные

[SHOWING THEMES](docs/SHOWING%20THEMES.md)

Всего 9 встроенных тем: `dark_default`, `light_default`, `midnight`, `forest`, `ocean`, `sunset`, `arctic`, `kanagawa_wave` (dark, из `rebelot/kanagawa.nvim`), `kanagawa_lotus` (light). Выбор в приложении: Settings → Theme.

#### Собственные

##### Вкратце

Положите `themes/my_theme.json` рядом с `config.json` или нажмите `Import` в настройках. Формат:

```json
{
  "id": "my_ocean",
  "name": "My Ocean",
  "mode": "dark",
  "seed": "#0066CC",
  "colors": { "primary": "#0066CC", "surface": "#101418" }
}
```

`seed` обязателен (генерирует M3-палитру), `colors` опционально перетирает любые токены `ColorScheme` (см. `themes/README.md` и `app/interface/themes/schema.py`). Валидация: `id` — 3–32 символа `[a-z0-9_]`, `name` — 2–40 символов, `mode` — `dark`/`light`, `seed` — hex `#RGB`/`#RRGGBB`/`#RRGGBBAA`. Легаси `"dark"/"light"` в `config.json` мигрируют на `dark_default/light_default`, несуществующая тема откатывается на `dark_default`.

##### Более подробно в [THEMES README](themes/README.md)

### 📚 Система коллекций

Хранилище — `favorites.json` рядом с `config.json`: только метаданные обоев, без бинарников. Запись атомарная, повреждённый файл пересоздаётся с настройками по умолчанию.

- Встроенная коллекция `Favorites` — неудаляемая; остальные коллекции создаются, переименовываются, очищаются и удаляются через интерфейс.
- Добавление: сердечко на плитке → `Favorites`; `+` → пикер коллекций. Коллекции, где обои уже есть, помечены галочкой и недоступны для повторного добавления.
- Режим коллекций открывается сердечком в шапке: плитки с обложками и счётчиком, создание, свойства, скачивание целиком (ZIP или папка).
- Обложка коллекции: последние обои, выбранные обои, иконка или сердечко.
- Слайдшоу: включение, интервал от 10 секунд (по умолчанию 300), порядок `sequential`/`random`, вписывание `fill`/`fit`. В фуллскрине слайдшоу ставится на паузу; неудачные элементы пропускаются.
- В открытой коллекции крестик удаляет обои, long-press включает множественный выбор: удалить / скачать / перенести / запустить слайдшоу.
- Скачивание коллекции: ZIP потоком на диск или папка; ошибки по отдельным файлам учитываются в итоговом сообщении.
- В `favorites.json` также поддерживаются read-only папки (`folders`): файлы не копируются и не изменяются. В текущем UI нет кнопки привязки папки — существующие записи отображаются и могут быть отвязаны.

### 📑 Структура конфига

[`config.example.json`](config.example.json) — пояснительная шпаргалка с комментариями, поэтому она не является строгим JSON. Готовый набор значений по умолчанию:

```json
{
    "MODE": "dev",
    "LOG_LVL": "DEBUG",
    "PORT": 9864,
    "APIK": "",
    "CHECK_UPDATES": true,
    "CHECK_PRERELEASES": false,
    "THEME": "dark_default"
}
```

- `MODE` — `dev` или `prod`. В `prod` отключается консольный вывод, логи пишутся в файл.
- `LOG_LVL` — `DEBUG`, `INFO`, `WARNING`/`WARN`, `ERROR`, `CRITICAL`; применяется при старте.
- `PORT` — порт локального сервера Flet (окно приложения); изменение требует перезапуска.
- `APIK` — ключ от [Wallhaven](https://wallhaven.cc/). Нужен для снятия ограничений на запросы и доступа к `sketchy`/`nsfw`; применяется без перезапуска.
- `CHECK_UPDATES` — проверять обновления при старте (по умолчанию `true`).
- `CHECK_PRERELEASES` — предлагать пре-релизы (по умолчанию `false`).
- `THEME` — выбор темы приложения, подробнее в разделе [«Система тем»](#-система-тем).

## 🗄 Структура проекта

- `app` — папка всего приложения.
  - `core` — ядро проекта: конфигурация (`config.py`), логирование (`logger.py` + `logger_config.py`), обработка ошибок (`error_handling.py`), реестр закрываемых ресурсов (`resources.py`), определение версии (`version.py`); `_version.py` генерируется при сборке.
  - `interface` — весь UI на `Flet`.
    - `bus.py` — шина событий `page.pubsub` между панелями (22 топика `ywallhaven/*`).
    - `components` — панели интерфейса: `left_panel.py` (поиск, фильтры), `middle_panel.py` (сетка), `right_panel.py` (превью), `collections_panel.py` (сетка коллекций и их содержимое), `collection_settings.py` (свойства коллекции, настройки слайдшоу), `settings.py` (настройки + темы), `update_dialog.py` (диалог автообновления).
    - `themes` — `schema.py`/`builtin.py`/`loader.py` — реестр тем, Kanagawa из `rebelot/kanagawa.nvim`, гибрид `seed+colors`.
    - `client_env.py` — чистка `LD_LIBRARY_PATH` для внешнего Flet-клиента в Linux-сборке.
    - `flet_app.py` — сборка панелей в единый layout.
  - `schemas` — `pydantic`-схемы: конфигурации (`config_schema.py`), апдейтера (`updater_schema.py`); `wallhaven_schema.py` — пустая заготовка.
  - `service` — бизнес-логика: `wallhaven_api.py` (клиент Wallhaven API), `updater.py` (автообновление), `wallpaper.py` (установка обоев: Windows/Linux-бэкенды), `favorites.py` (хранилище Избранного и коллекций), `collection_io.py` (скачивание коллекции в ZIP/папку), `slideshow.py` (движок слайдшоу).
  - `main.py` — точка входа: режим приложения, логирование, запуск Flet.
- `updater/` — отдельный executable для автообновления (`main.py`).
- `docs/` — документация и ассеты: `docs/assets/` (`icon.png`, `icon.svg`; `icon.ico` генерируется при сборке).
- `themes/` — пользовательские темы `*.json` + неактивные примеры `example_*.json.example` (см. `themes/README.md`).
- `scripts/` — `build.py` (сборка win/linux по `--target`: версия, иконка, PyInstaller), `make_appdir.py` (AppDir для AppImage), `package_release.py` (zip + `SHA256SUMS.txt`), `smoke_wallhaven.py` (живой чек API без моков).
- `tests/` — общие pytest-тесты; `tests/native/` — native-проверки ОС (`native_linux`, `native_win`).
- `ywallhaven*.spec` — PyInstaller-спеки: Windows (`ywallhaven.spec`, `ywallhaven-updater.spec`) и Linux (`ywallhaven-linux.spec`, `ywallhaven-updater-linux.spec`).
- `.github/workflows/tests.yml` — тесты на push/PR и вызов из релизного workflow.
- `.github/workflows/build-release.yml` — CI-сборка и публикация релизов.
- `run.py` — шим для PyInstaller-спеков, вызывает `app.main.main`; для запуска из исходников используйте `uv run app/main.py`.
- `config.example.json` — пояснительная шпаргалка по конфигу (не строгий JSON).
- `config.json`, `favorites.json`, `logs/` — создаются приложением и игнорируются git.
- `pyproject.toml` и `uv.lock` — конфигурация проекта и зависимости.
- [`README.md`](README.md) — этот файл; [`README.en.md`](README.en.md) — английская версия.
- [`CHANGELOG.md`](CHANGELOG.md) — список изменений в проекте.
- [`LICENSE`](LICENSE) — лицензия проекта.

## 🤝 Правила внесения изменений в код

- Для багфикса сначала воспроизведите проблему и добавьте или обновите тест в `tests/`.
- Соблюдайте PEP 8 (4 пробела, до 79 символов), PEP 257 и type hints; не оставляйте `except Exception: pass`.
- Перед PR выполните `uv sync` и `uv run pytest`; для изменений UI и сервисов запускайте соответствующие тесты.
- Пользовательские изменения отражайте в `README.md`/`README.en.md` и `CHANGELOG.md`.
- Не коммитьте `config.json`, `favorites.json`, `logs/`, `dist/`, `.venv` и API-ключи.
- Крупные архитектурные изменения обсуждайте в Issue до реализации.
